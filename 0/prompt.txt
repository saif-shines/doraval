27→## Release / npm platform packages (learned the hard way)
28→
29→**Incident source:** Claude session `bdd5e085` (2026-07-08/09, B1 first ship) + commits `9389365`, recovery for v0.5.0–0.5.2. Same failure pattern on **v0.6.0**.

31→### Symptom
32→
33→CI `publish-npm` logs:
34→
35→```
36→npm notice publish Signed provenance statement…   # only when --provenance is on
37→npm error code E404
38→npm error 404 Not Found - PUT https://registry.npmjs.org/@hacksmith%2fdoraval-darwin-arm64
39→```
40→
41→Main `@hacksmith/doraval` may still publish. Platform packages stay on an older version → **broken install**: optionalDeps point at missing binaries; stub says "platform package is not installed."

43→### Wrong diagnosis (do not repeat)
44→
45→"Granular access token can't create new package names under the scope" — **disproven**. Same token published the packages successfully from a local shell.
46→
47→### Confirmed diagnosis
48→
49→- Failure is **auth/permissions on the five platform packages**, not a missing package-ACL list in the general sense.
50→- **`npm publish --access public` without `--provenance` from a local shell works** when the token can publish (or you pass `--otp=<code>` for 2FA).
51→- CI historically failed with `--provenance` on platforms (provenance signed, then PUT 404). CI was patched to drop provenance for platforms only (`9389365`); main still uses `--provenance`.
52→- **v0.6.0 recovery (2026-07-14):** whoami worked but publish returned **EOTP** until `npm publish --otp=…`. All five platforms published locally from GH release binaries. npm may return **E404** when the token lacks write/Bypass-2FA — do not misread that as "package missing."
53→- If platforms still 404/EOTP in CI, **do not ship main alone** and do not invent new version bumps — recover with the local procedure below. CI `NPM_TOKEN` should be a granular token with **write + Bypass 2FA** on all five platform packages (and main).
54→
55→### Recovery procedure (when CI platform publish fails)
56→
57→Do **not** bump the version. Reuse the release tag's binaries.
58→
59→```bash
60→# 1) Download GitHub Release artifacts for the tag (e.g. v0.6.0)
61→TAG=v0.6.0
62→VERSION=${TAG#v}
63→SCRATCH=$(mktemp -d)
64→mkdir -p "$SCRATCH/artifacts"
65→for f in doraval-darwin-arm64 doraval-darwin-x64 doraval-linux-x64 \
66→         doraval-linux-arm64 doraval-win32-x64.exe; do
67→  curl -fsSL "https://github.com/saif-shines/doraval/releases/download/${TAG}/${f}" \
68→    -o "$SCRATCH/artifacts/${f}"
69→done
70→
71→# 2) Assemble platform packages (same as CI)
72→bun run scripts/platform-packages.ts "$VERSION" "$SCRATCH/artifacts" "$SCRATCH/platform-packages"
73→
74→# 3) Publish EACH platform package LOCALLY — no --provenance
75→#    If EOTP: npm publish --access public --otp=XXXXXX  (or use a Bypass-2FA GAT)
76→for dir in "$SCRATCH/platform-packages"/*/; do
77→  (cd "$dir" && npm publish --access public ${OTP:+--otp="$OTP"})
78→done
79→
80→# 4) Verify all five exist at $VERSION
81→for p in darwin-arm64 darwin-x64 linux-x64 linux-arm64 win32-x64; do
82→  npm view "@hacksmith/doraval-$p@$VERSION" version
83→done
84→
85→# 5) Main package: only if missing for this version
86→#    bun run scripts/prepare-npm-publish.ts && npm publish --access public --provenance
87→#    then: git checkout -- package.json   # NEVER commit injected optionalDependencies
88→```
89→
90→**Rules:**
91→
92→- Never commit publish-time `optionalDependencies` injection (`prepare-npm-publish.ts` is CI-only).
93→- Never publish main until all five platform packages are on the registry (workflow is fail-fast; keep it that way).
94→- Prefer binaries from the **GitHub Release for that tag**, not a stale local smoke binary (session bug: mismatched darwin-arm64 content vs other arches).
95→- After recovery: verify with real install (`npm install @hacksmith/doraval@$VERSION` in a clean dir, then run `doraval --version`) — `npx` can hide optionalDep failures.
